# PoGo Companion — review report, branch `cleanup/native-pill-scan` (HEAD d4f86e4, 40 commits ahead of `origin/main` 98f8430)

Line numbers below are HEAD's. The verified findings for `index.html` ≥ line 1480 were taken on a snapshot before b7ca0cf (log-identity rewrite); on HEAD they sit ~20 lines lower, and the three log-persistence findings were re-checked against the new `findLogEntry()` (see M7). Kotlin, workflow and resource line numbers are unchanged.

## 1. Executive summary

1. **Merge the CI part of this branch to `main` today.** The workflow live on `main` generates the APK signing key inside the checkout with password `pogo2026pass` and uploads the whole tree to GitHub Pages, so the keystore and password are public and anyone can sign an APK that installs as an "update" over every v2.0.0 install. Commit 1fcc37b on this branch fixes it; nothing else on the branch needs to land for that. Treat the old key as burned.
2. **Not safe to ship as the next APK until four things are fixed:** the deploy job must fail (not warn) when signing secrets are missing, or it publishes an uninstallable "update" to every user; a WebView renderer kill crashes the whole app and drops the pill mid-session; the consent explainer makes three false claims (SCAN-only, nothing saved, nothing sent) that a Play reviewer would call deceptive; the pill's four buttons are dead under TalkBack/switch access.
3. **Verdict engine is mostly right but has seven rule defects**, the worst being: all-Transfer families (Caterpie, Zubat, ...) get gold KEEP "EVOLVE TO ..." slots; final-form PvP species (Azumarill, Lapras, ...) are told "TRANSFER (TRADE PRIORITY LOW)" while `tradePriority()` says HIGH; luckies rank #1 yet read "YOU HAVE 6 BETTER".
4. **Species identification is wrong for whole families:** Nidoran♂/Nidorino/Nidoking are logged as the female line, every regional form (Alolan Exeggutor, Galarian Zapdos in storage, ...) is logged as the Kanto form, both with `ambiguous:false`.
5. **Delivery is fragile on both channels:** PWA Force Reload permanently kills offline mode; any page change without a `CACHE_NAME` bump (HEAD is one) never reaches existing visitors, and without a `versionCode` bump never reaches APK users; My Log import can brick the modal permanently.

## 2. Findings by severity

### High

**H1. Signing key and password are published on the live site** — `origin/main:.github/workflows/deploy-pages.yml:38-46,73`; `origin/main:android/app/build.gradle.kts:25,27`.
Player impact: any third party can build `com.pogo.companion` signed with the same key; Android installs it over the deployed v2.0.0 population as a legitimate update. Fix: merge (or cherry-pick 1fcc37b: keystore in `$RUNNER_TEMP`, scrub step at branch lines 73-77) so the next Pages deploy replaces the site without the `.jks`. The permanent key already forces one uninstall (`tools/setup-signing.sh`), so tell v2.0.0 users to reinstall rather than update.

**H2. WebView renderer death crashes the app, pill and projection** — `MainActivity.kt:70` (`webView.webViewClient = WebViewClient()`).
With Pokémon GO in front for an hour and the stopped activity holding the 2.3 MB dataset plus a pre-warmed Tesseract worker (`index.html:3485-3486`), LMK reclaims the renderer; the default `onRenderProcessGone` returns false, WebView throws, the process dies (`START_NOT_STICKY`, `FloatingOverlayService.kt:186`), user sees "keeps stopping" over the game and must redo consent. Fix: custom `WebViewClient` overriding `onRenderProcessGone` → `true`, remove/destroy the WebView, set `OverlayBus.ocrEvaluator = null` (the service already renders "APP WAS CLOSED / TAP OPEN, THEN MINIMIZE AGAIN" when the evaluator is null, `FloatingOverlayService.kt:795-813`), then recreate the WebView or wait for OPEN. Also stop pre-warming Tesseract in the APK (L30).

**H3. Consent explainer is false on three counts** — `res/values/strings.xml:6`.
"Only read when you tap SCAN": AUTO re-samples every 1.2 s for up to 10 min with no tap (`FloatingOverlayService.kt:89-100,145-147`). "Nothing is ever saved": every storage scan is written to localStorage `pogo_log_v1` with family, size, CP, IVs, date, place (`index.html:1489-1520`), raw OCR lines shown under "Last scan details". "Nothing sent anywhere": `allowBackup="true"` (`AndroidManifest.xml:12`) puts WebView storage into Google auto-backup; `UpdateChecker.kt:48` hits GitHub every launch. Shown once ever (`MainActivity.kt:127-140`), so anyone who consented before AUTO existed was never told. Fix: rewrite the string (SCAN reads one frame; AUTO keeps reading while on; scans saved in My Log on this device and in your Android backup; a version check contacts GitHub; no screen content uploaded); store an int text-version instead of the boolean so a changed text re-shows; decide `allowBackup` (owner).

**H4. Pill buttons unusable with TalkBack / switch access; targets and text too small** — `FloatingOverlayService.kt:274-277,283-335`; `floating_pill.xml:93-125`; `themes.xml:16,26`.
All four controls are wired only through `setOnTouchListener` (returns true, fires `onTap` only from a real `ACTION_UP`); `v.performClick()` at 326 has no `OnClickListener`, so accessibility `ACTION_CLICK` does nothing. OPEN/CLOSE are ~36×19 dp, text 7-9.5 sp. Fix: in `attachDragOrTap` put `vibrateTap(); onTap()` into `view.setOnClickListener {}` and keep the touch listener for drag only (its existing `performClick()` on a non-drag UP then converges both paths); `minHeight` 48 dp or `TouchDelegate`; `ViewCompat.setAccessibilityDelegate` with role "button" and `stateDescription` for AUTO. Colour is the only difference between gold KEEP and purple KEEP; add the word ("INVEST") to the slot text.

**H5. Nidoran♂ line identified as Nidoran♀** — `index.html:3653` (also `3621`, `3552-3575`).
`key()` strips ♀/♂; `POKEMON_DATA.find` returns Nidoran♀ (id 29 precedes 32), so "NIDORAN♂ CANDY" → family [Nidoran♀, Nidorina, Nidoqueen] → a Nidoking at 2500 CP is logged, IV-checked and verdicted as Nidoqueen, `ambiguous:false`. Same via the banner path. Fix: in all three key helpers map `♀→'f'`, `♂→'m'` before the `[^a-z0-9]` strip; when neither symbol was read, use the union of both Nidoran lines as the family and let CP/name/`ambiguous` decide.

**H6. Regional forms and branched cocoons are never candidates** — `index.html:3669`.
`family = filter(p === base || p.evo === base.evo || base.finals.includes(p))`. "Exeggutor (Alola)" has evo "Exeggutor (Alola)" so it is excluded: an Alolan Exeggutor is logged as Kanto Exeggutor with the Kanto CP tables (wrong "MAYBE 100%") and verdict, `ambiguous:false`; same for Meowth/Raichu/Marowak (Alola), Zapdos (Galar) in storage, etc. Same line drops Silcoon ("Beautifly") and Cascoon ("Dustox") from the Wurmple ("Beautifly / Dustox") family, so a Silcoon with EVOLVE visible is logged as Wurmple. Fix: build the family by base species name (`baseSpecies()` on every member of the line and its finals) plus transitive finals intersection; if more than one form survives, use the banner form prefix when the appraisal is open, otherwise return `ambiguous:true` (owner decision on how that is surfaced, see §4).

**H7. Force Reload permanently disables offline mode** — `index.html:4441-4448`; `sw.js:14-19,33-57`.
`applyAppUpdate` deletes every cache (un-awaited) and reloads; `sw.js` is byte-identical so `install/addAll` never re-runs, and the on-the-fly `cache.put` only matches CDN/png/wasm/traineddata URLs, never `index.html`/`manifest.json`/`icon.svg`. Next offline launch: `caches.match` misses, fetch rejects, the catch returns `cachedResponse` (undefined) → `respondWith(undefined)` TypeError → Chrome "No internet" page, until the next `CACHE_NAME` bump. Fix: in `applyAppUpdate` `await Promise.all(names.map(n => caches.delete(n)))`, then `(await navigator.serviceWorker.getRegistration())?.unregister()` (or postMessage the SW to re-run `addAll`), then reload; in `sw.js` cache same-origin navigation/document responses on the fly (network-first for `./index.html`) and in the catch return `caches.match('./index.html')` for `e.request.mode === 'navigate'`.

### Medium

**M1. Deploy without signing secrets ships an uninstallable update to everyone** — `.github/workflows/deploy-pages.yml:43-54`.
Missing/rotated secrets → `::warning`, random key, build, stage `pogo-companion.apk`, regenerate `version.json` with the current `versionCode`, upload `.`. Every installed APK is offered the update; installer says "package conflicts with an existing package"; repeats each cold start until "Skip this version", which also suppresses that code when the real build lands. Fix: replace the `else` branch with `echo '::error::KEYSTORE_BASE64/KEYSTORE_PASSWORD not set'; exit 1` (keep the throwaway path in `build-apk.yml`, which never deploys).

**M2. All-Transfer families get gold KEEP "EVOLVE TO X WHEN CANDY ALLOWS"** — `index.html:1704-1706`.
Two appraised Caterpie (39 and 36): the 39 is rank 1, `inRaid` true, not surplus, total < 41, so 1704 fires (`rankTag && poolIsFamily && finals.length && !surplus`) → KEEP, gold. A Butterfree in the same position stays DELETE '+1 CANDY'. 351 families affected. Fix: add `&& (p.plan === 'grow' || p.finals.some(f => !f.act.includes('Transfer')))` to the condition at 1704.

**M3. Surplus TRADE requires `candyGoal()`; SURPLUS text hard-codes "(TRADE PRIORITY LOW)"** — `index.html:1690-1695`; `candyGoal` 1873-1876.
`candyGoal`'s `valuableFamily` ignores `act.includes('PvP')` and legendaries with no further evolution (finals = []), so for 121 final-form species (Azumarill, Blastoise, Lapras, Steelix, Raikou, Mew, ...) `goal` is null while `tradePriority()` is HIGH → verdict SURPLUS with a false "LOW" label. Fix: decide on `prio === 'HIGH'` alone, append the goal only when present (`... LUCKY CHANCE${goal ? ' + CANDY. ' + goal : ''}`), print `(TRADE PRIORITY ${prio})`; optionally extend `valuableFamily` with `p.act.includes('PvP') || p.isLegendary`.

**M4. `trade_evolve` species below floor / over quota are told to transfer** — `index.html:1689-1695`.
Single Machoke 12/12/12: base rule TRADE 'FREE EVOLVE AFTER TRADE'; `belowFloor` → surplus; `tradePriority(Machoke)` LOW (Machamp ranks > 100) → "MACHOKE – BELOW THE 37-IV FLOOR – TRANSFER FOR CANDY (TRADE PRIORITY LOW)". A trade re-rolls the IVs and saves the whole evolution cost, so the floor is irrelevant. Same for Graveler, Karrablast, Shelmet, Phantump, Pumpkaboo. Fix (owner decision, §4): before the transfer branch, `if (p.plan === 'trade_evolve' && !c.dynamax && !c.marks.includes('shadow')) g = { ...g, reason: \`${tag} – FREE EVOLVE AFTER TRADE (IVs RE-ROLL)\` }`, or make `tradePriority` return HIGH for `trade_evolve`.

**M5. Lucky bonus counts toward rank but not the floor; surplus texts assert "YOU HAVE n BETTER" with nothing better** — `index.html:1683,1716,1754`; `entryScore` 1551-1560 vs `meetsRaidFloor` 1564.
A lucky 12/12/12 Machamp ranks #1 (36+6) but fails the 37 floor → surplus → "#1 OF 3 MACHOP FAMILY – LUCKY, BUT YOU HAVE 6 BETTER" in red, contradicting the legend (723: a lucky is never told to give it up). Alone: " – LUCKY, BUT YOU HAVE 6 BETTER". Same fixed-`keepN` text at 1716 (Dynamax) and 1754 (favorite). A below-floor lucky also occupies a top-n slot and pushes a floor-meeting sibling to rank n+1. Fix: word by cause (`belowFloor ? floorNote : \` – YOU HAVE ${c.rank - 1} BETTER\``), and either apply `luckyBonus` inside `meetsRaidFloor` for lucky entries or exclude below-floor entries from the rank used by `inRaid`.

**M6. AUTO frames include the pill, but only OCR lines are masked** — `FloatingOverlayService.kt:572-577` (detectors), `591-600`, `606-621`, `628-686`; mask only in `evaluate()` 774-781.
Manual SCAN blinks the pill out (552-562); AUTO never does. Left dock (`PREF_PILL_SIDE`, 80 dp at x=10) covers the 0.12W/0.20W storage sample columns → "not a storage page", every card skipped; over the appraisal bars `readIvBars` probes the pill background → IVs null. Right dock dragged to y=0 covers the star region → `looksFavorited` false → favorite protection bypassed. The comment at 588-590 still assumes right dock only. Fix (owner decision): hide the pill for the AUTO frame as `requestScan()` does, or pass the scaled `pillRect` into the detectors and skip intersecting sample points (treat a bar whose ±12 px probe lands in the pill as unverifiable, not rejected).

**M7. Log identity (re-checked against HEAD's `findLogEntry`, `index.html:1603-1625`; `recordStorageScan` 1489-1520).** The scoring rewrite in b7ca0cf changed all three verified findings; current state:
- (a) **Two different same-species, same-CP Pokémon still merge.** A sized scan whose size does not match scores species +1, CP +2, "just scanned" +2 (or same catch date +2) = 5 ≥ 4 → merged into the other Pokémon; its size is kept (1509 only fills when missing), its IVs are overwritten (1508). Common for 10 CP research rewards and box mass-scans. Fix: add a hard contradiction after line 1611: `if (sized && e.weight != null && e.height != null && !near(e.weight, details.weight, 0.02) && !near(e.height, details.height, 0.01)) continue;`.
- (b) **Sizeless (appraisal-open / AUTO) entry and sized scan reunite only if the catch date was read on both.** Otherwise species +1, CP +2 = 3 < 4 → second entry, pill says "not appraised", family count +1. Fix: a sizeless entry cannot contradict on size, so give it the either-dimension credit: `if (sized && e.weight == null && e.species === pokemon.name) score += 1;`.
- (c) **Evolution:** the old entry now migrates only when the first post-evolution scan has the appraisal open (IVs +3, date +2); with it closed (species/size/CP all changed) a fresh entry is created and the pre-evolution ghost keeps a keep-N slot. After a migration the stale size is never refreshed because 1502 sets `entry.species` before 1509 compares. Fix: `const evolved = entry.species && entry.species !== pokemon.name;` before 1502, then `if (sized && (!entry.weight || evolved)) { ... }`; add an "evolved/transferred" removal action or age out unseen entries when a family exceeds keep-N (owner decision).
- Note: lines 1497-1501 are a second `if (!entry)` block that can never run (left over from the rewrite).

**M8. Import saves before validating; one bad entry bricks My Log forever** — `index.html:1861-1864`; `renderSpeciesSummary` 1787; `renderLogModal` 1807; `openLogModal` 1762.
`[{"id":"x1","family":"Charmander"}]` passes the `id && family` filter, `savePokeLog()` runs, then `best.ivs` (1787) or `a.species.localeCompare` (1807) throws; the user is told "not a valid log backup" but the entry is persisted, and `openLogModal` throws every time, so Clear all/remove are unreachable (only wiping app data helps). `"ivs":"15/15/15"` corrupts scoring the same way. Fix: validate each entry (string `species` known to `POKEMON_DATA`, string `family`, `weight/height` number|null, `ivs` null or three ints 0-15, `cp` int|null, booleans), drop invalid ones, render before saving (save inside the `try` after `renderLogModal()` succeeds), and make `renderLogModal` defensive (`String(e.species || '')`).
